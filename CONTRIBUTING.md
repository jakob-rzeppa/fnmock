# Contributing to fnmock

Thanks for taking an interest in fnmock. Contributions are welcome.

First, check the [support matrix](docs/LIMITATIONS.md) first. If you see a bug or missing documentation / tests, please open an issue.

For small bug fixes, feel free to open a PR with just the fix and tests. For larger features, open an issue first to discuss the design and get feedback before you start coding.

This project puts a high value on the tests in `fnmock-tests` and the support matrix in [LIMITATIONS.md](docs/LIMITATIONS.md). So a new feature or bug fix should be accompanied by a test in `fnmock-tests` and a row in the support matrix.

## Releases

Releases are cut manually by the maintainer from a green `master`, following
[RELEASE.md](docs/internal/RELEASE.md). Contributors do not need to bump versions or edit
[CHANGELOG.md](CHANGELOG.md) in a pull request.
